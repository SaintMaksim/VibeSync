# Техническое задание на проект: «VibeSync»
## 1. Цель проекта
Создание веб-платформы для коллективного создания музыкальных плейлистов для мероприятий. Система позволяет организаторам событий (вечеринок, свадеб, корпоративов) создавать виртуальные мероприятия, куда гости могут предлагать треки и голосовать за них. Платформа автоматически формирует сбалансированный финальный плейлист с учетом жанрового разнообразия и предпочтений участников, решая проблему музыкальных разногласий на мероприятиях.

## 2. Роли пользователей
Гость: Может перейти по ссылке мероприятия, просматривать текущий плейлист, предлагать треки через поиск, голосовать за предложенные треки (лайк/дизлайк).

Авторизованный пользователь: Все возможности гостя + создание собственных мероприятий, управление настройками своих мероприятий, завершение голосования и экспорт финального плейлиста.

## 3. Модели данных
Event (Мероприятие): Основная сущность, представляющая мероприятие.
Поля: title (название), description (описание), host (связь с User, организатор), access_code (уникальный код для ссылки), created_at (дата создания), ends_at (окончание голосования), is_active (активно ли), max_genre_percent (максимальный процент одного жанра), mood_sequence (алгоритм последовательности настроения).

Track (Трек): Музыкальная композиция, полученная из внешних источников.
Поля: title (название), artist (исполнитель), lastfm_id (ID в Last.fm), duration (длительность), tags (теги/жанры через запятую), added_at (дата добавления).

TrackSuggestion (Предложение трека): Связь между треком и мероприятием, предложение трека для конкретного мероприятия.
Поля: event (связь с Event), track (связь с Track), suggested_by (связь с User, кто предложил), votes_score (суммарный рейтинг голосов), suggested_at (дата предложения).

## 4. Ключевой функционал
- Создание мероприятия: Авторизованный пользователь заполняет форму с названием, описанием, настройками балансировки и получает уникальную ссылку для гостей.

- Поиск и предложение треков: Гость вводит название трека в поисковую строку, система находит трек через Last.fm API, отображает информацию (исполнитель, теги), и гость может предложить его для мероприятия.

- Голосование за треки: На странице мероприятия гости видят список предложенных треков и могут голосовать за них (лайк/дизлайк). Рейтинг каждого трека обновляется в реальном времени.

- Алгоритмическая балансировка плейлиста: После завершения голосования система анализирует предложенные треки, учитывает их теги (жанры), применяет настройки балансировки (максимальный процент жанра, последовательность настроения) и формирует оптимальный порядок треков в финальном плейлисте.

- Визуализация и экспорт: Система отображает диаграмму распределения жанров в плейлисте. Организатор может экспортировать финальный плейлист в виде текстового списка.

## 5. Внешние интеграции и аналитика
Интеграция: Использование Last.fm API для поиска треков и получения их тегов (жанров). API позволяет получать информацию о миллионах треков с детальными метаданными.

Аналитика: Использование библиотеки Pandas для анализа тегов треков и классификации их по жанрам. Применение простых алгоритмов для балансировки плейлиста на основе полученных данных. Использование Chart.js для визуализации распределения жанров в виде диаграмм на странице мероприятия.
